# ScaleDown 使用方式调整与 khipaa 复测

**客户端已显式关闭 ScaleDown classify 的 reasoning；本轮仍建议默认纯 Jev。** 纯 Jev 最快，六类决策标签准确率也更高。SD → Jev 在话权二分类上略好，但多约 120ms，该准确率优势的 family 区间跨过 0。未合并、未部署。

## 改了什么

- `/v1/scaledown`、`model=classify-1` 的顶层 body 增加 `"reasoning": false`，覆盖所有直接 SD 决策。
- SD → Jev 是 `/compress/raw/` 后串行调用 Jev，没有 SD classify 请求；不向压缩或 Jev 接口添加未经确认的 reasoning 参数。
- 不改 prompt、阈值、800ms 总截止时间、默认纯 Jev、engine 或 UI 行为。已有 HTTP 取证会保留实际请求 body。

## 测量设计

基于当前 `5ed692cf78bde417c553b8e798e13d647afcd29c`，而不是前一轮旧 prompt。219 个既有回归输入、126 个 family；热连接每个输入每组重复 3 次，四组顺序轮换、2 个 worker。三个主路径之外增加 reasoning=true 对照。另有 20 个固定样本 × 2 次冷连接，以及 156 个话权样本各模式实际配置的一次对比。

样本全部此前已见，未按这轮结果调 prompt/阈值/gold。63 条旧六类记录共 101 个 exact-choice 标注；156 条话权状态来自 108 个作者合成/公开参考转录 family，属于二分类或代理 gold。**不是新盲测，不是新真实通话/人耳评测。** 准确率分任务报告，重复次数不是独立样本数。

主测统一当前 Jev 的 prompt/criteria、输入和判分阈值，隔离模型路径；附加实际配置测量保留各模式自己的 prompt/阈值，不能当作纯模型差异。SD API 使用序列化 text，组合路径保留真实压缩输出。

## 主测：相同 prompt、热连接

每个路径 657 次请求链（219 输入 × 3）；六类标签 303 次判定（101 × 3）；话权准入 468 次判定（156 × 3）。以下是 API 请求链耗时，不含 ASR/LLM/TTS，不代表声音响应时间。

| 路径 | P50 ms | P95 ms | P99 ms | 六类标签正确 | 话权准入正确 | >800ms |
|---|---:|---:|---:|---:|---:|---:|
| 纯 Jev | 94.8 | 140.4 | 166.5 | 289/303（95.4%） | 432/468（92.3%） | 0/657 |
| 纯 SD（reasoning=false） | 261.8 | 409.3 | 454.3 | 269/303（88.8%） | 413/468（88.2%） | 0/657 |
| SD 压缩 → Jev | 215.6 | 276.5 | 388.8 | 278/303（91.7%） | 441/468（94.2%） | 0/657 |
| SD（reasoning=true 对照） | 261.0 | 412.2 | 471.1 | 270/303（89.1%） | 413/468（88.2%） | 1/657 |

三个主路径均无 HTTP/分布解析错误，主测均未超过 800ms；reasoning=true 对照出现 1 次超时。表中话权准入采用当前 Jev 的 chosen-label 条件与 answer+clarify 合分规则；对照那次超时计入截止时间后为 412/468，而非 413/468。

组合路径的压缩阶段 P50/P95=118.2/132.5ms，后续 Jev=93.6/143.7ms；链路总耗时已完整计入。它虽然有两次串行调用，仍比纯 SD 快，因为压缩和 SD classify 是不同接口/工作量。

### 六类标签分项

| 类型 | Jev | SD false | SD → Jev |
|---|---:|---:|---:|
| start | 51/54 | 36/54 | 50/54 |
| stop | 33/33 | 33/33 | 33/33 |
| backchannel | 24/24 | 21/24 | 24/24 |
| compression | 12/12 | 12/12 | 6/12 |

其中 compression 只有 4 个独立输入，重复后 12 次，组合仅 6/12；不要把压缩后的话权准确率提升推广到所有决策。各 source/cohort 的分母、错误、延迟以及三次重复的标签变化保留在 `results/metrics.json`。

| 对比 | 平均延迟差 ms，95% CI | 六类准确率差 pp，95% CI | 截止时间内话权准确率差 pp，95% CI |
|---|---|---|---|
| sd-minus-jev | +170.9 [+159.8, +182.2] | -6.6 [-14.9, +3.3] | -4.1 [-8.5, +0.2] |
| sd_jev-minus-jev | +123.6 [+119.4, +128.0] | -3.6 [-7.0, -0.3] | +1.9 [-0.8, +4.7] |

链路相对 Jev 的话权优势约 +1.9pp，但区间 −0.8 至 +4.7pp，尚不足以建议替换默认。样本标签本身的不确定性不包含在统计区间中。

## reasoning 开关：目前没有观察到显著提速

同一输入的 657 对 SD false/true，平均延迟差为 false−true = −1.4ms，family bootstrap95% [−8.8,+5.5]ms。两组 P50 均约 261ms。657/657 对报告的 output_tokens 完全相同；两组都没有任何 reasoning 文本字段，504/657 对整个 answers 对象完全相同。其余存在概率或选择差异，不能据此推断内部解码策略。

因此只能确认**请求已经显式发送 false 且接口接受**，不能确认当前 `/v1/scaledown` 兼容接口实际使用了该字段，或 true 是否真的开启 reasoning。提供方宣称专用资源已开启属于环境背景，无法从前后不同时间/不同样本的结果分离其因果收益。对照原始响应已保留；没有 reasoning 文本可供进一步追踪。

尝试读取该服务公开文档/openapi 路径均返回 403 `Missing Authentication Token`，带现有 API key 也相同；未据此猜测新的 endpoint、请求字段位置或模型名称。需要供应商确认当前接口的字段位置、是否启用以及为何 true 不返回 reasoning。没有自动向 Slack 发消息。
